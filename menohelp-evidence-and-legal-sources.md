## Data-flow observations

Cycle uploads -> FastAPI memory -> computed statistics -> OpenAI report generation. Lab PDFs -> local parser -> structured measurements -> memory and OpenAI. Symptom answers/free text -> summaries and generation; free-text concern can also go to OpenAI embeddings -> query vector to Supabase. Supabase supplies stored reference/coaching chunks. The report -> UI/download; optional report, chart and recipient address -> Resend -> recipient mailbox. Local identifier removal reduces exposure but does not prove GDPR anonymisation. Vendor retention, hosting regions, contracts and account-specific settings were not available.

## Course materials reconciled

Read: the supplied LAB 3 page, Compliance Legal and the AI Consultant, EU AI Act for Consultants, Roles GPAI and Liability Boundaries, Discussion Prep, GitHub Labs and AI Feedback, and both lesson slide decks. The lab repository's instructions and rubric define the report sections and debrief. The portal additionally requires `lab_proof.md`, a workflow/run, its input and evidence, final output and a limitation. The portal names Project 3 while the repository says SilverTrust; this review follows the user's specifically named Menohelp project.

Course checklists are teaching summaries. In this report, high-risk duties remain conditional on classification and applicability; Article 49 registration is not treated as a universal requirement for every Annex I medical device. GPAI is an upstream regulatory layer, not a fifth mutually exclusive product-risk class. We do not transfer OpenAI's model duties to the application builder or assume an unverified systemic-risk model designation. The slide shorthand on profiling is read within Article 6(3)'s Annex III context.
